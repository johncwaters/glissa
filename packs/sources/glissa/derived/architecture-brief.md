# Glissa Architecture Brief

## What Glissa is

Glissa is a lightweight Node.js background process that spawns and manages Claude Code sessions via node-pty, streams terminal output to a browser dashboard over WebSockets, derives each session status from structural signals (Claude Code hooks plus an OSC-0 title fallback, never screen scraping), and notifies the operator through browser notifications. The problem it solves: running many long Claude Code sessions at once and knowing, without watching every terminal, which one finished, which one is waiting for input, and which one failed. It is a single-user dev tool bound to localhost (no auth on the WebSockets; an opt-in remote mode adds a second, cookie-authenticated listener). Distribution is the GitHub repo only, `npm i -g github:johncwaters/glissa` (npm 12 or newer); the package is `private: true` and never published to the npm registry.

## Subsystems

- **server/**: the backend runtime. `server/backend.js` is the Express plus WebSocket server factory (shared by the `server.js` production entry and the Vite dev plugin), `server/control-handlers.js` dispatches control-WS messages (kill, restart, rename, settings), `server/config-store.js` owns config.json resolution (GLISSA_CONFIG env via `--config`, in-repo `config.json`, then `~/.glissa/config.json`, seeded if none), `server/spawn-gate.js` serializes `pty.spawn` initiation (ConPTY wedges under concurrent spawns), `server/git-workspace.js` is the ONLY module allowed to run `git worktree`, and `server/child-process-safe.js` is the ONLY module allowed to import node:child_process. Pure decision logic lives under `server/core/` (origin policy, request trust, pairing tokens, upload rules, and more).
- **session/**: the session domain. `session/sessions.js` is the stateful Session class (lifecycle, PTY spawn and kill, timers, hook ingestion); everything decidable without IO is extracted into `session/core/` (state machine tables, `status-mapper.js`, `agent-tracker.js`, `gate-release.js`, `spawn-command.js`, `spawn-env.js`, `auto-resume.js`, others). `session/session-recorder.js` writes an always-on JSONL forensic recording per session to `~/.glissa/recordings` (signals by default, raw PTY bytes opt-in).
- **detection/**: status detection. `detection/hook-source.js` (HookRouter) validates the per-session bearer token and maps Claude Code hook callbacks to signals; `detection/osc-title-source.js` reads the OSC-0 title glyph; `detection/status-source.js` merges the two (hook wins, conflict window, dedup); `detection/settings-injector.js` writes the per-session `--settings` file that injects the HTTP hooks; `detection/replay.js` replays recordings through detection for regression fixtures.
- **notifications/**: `notifications/notification-manager.js` is the lifecycle state machine (states in `shared/notification-states.js`). The primary channel is `channels/web-notification.js` (control-WS broadcast, the browser raises the native Notification); `channels/toast.js` (OS toast) and `channels/telegram.js` (pings the phone only when zero control connections are open) are opt-in. Focus suppression is per connection and defers delivery, never drops it.
- **packs/** (the context mill): specs in `packs/specs/<name>.pack.json` and sources in `packs/sources/**` are version-controlled with Glissa; built output is runtime state under `~/.glissa/packs/built/<name>/current/`. `server/core/pack-core.js` is the pure planner (spec validation, glob matcher, chars/4 token estimate, deterministic build plan whose version is a hash of every delivered file); `server/pack-builder.js` is the IO shell with atomic publish; `server/pack-service.js` auto-rebuilds via debounced watchers plus a 15 minute fallback sweep. Budgets are hard gates (`budgetTokens` per pack, `MAX_INDEX_TOKENS` on the CLAUDE.md index); a failed build writes nothing.
- **public/**: the browser dashboard, ES modules bundled by Vite. One xterm.js Terminal per session card; two first-class layouts (desktop and phone) chosen by the single predicate `decideLayout` in `public/form-factor-core.mjs` (phone requires a coarse pointer AND width at or below 768px). Live elements are re-parented across layouts, never duplicated; `public/card-host.js` is the one card-borrow seam with a global single-borrower invariant.

## Key seams

- **Pure core plus thin IO shell.** Every subsystem keeps its decisions in an IO-free module (`session/core/`, `server/core/`, `*-core.mjs` in the browser) with a thin shell doing the reads, writes, and timers. New pure logic gets a unit test in `tests/`.
- **EventEmitter between modules.** Inter-module communication is Node EventEmitter events (`state-change`, `pack-updated`, `claude-session-id`), never globals or direct coupling.
- **Dual WebSocket transport.** The data WS (`/terminals/:sessionId`) carries raw PTY bytes both ways; the control WS (`/control`) carries JSON messages (snapshot, state-change, kill, restart, settings). The `ws` package is used directly, never Socket.IO. Resize is arbitrated by active viewer (`server/core/viewer-size-core.js`), not last write.
- **Spawn path.** Sessions spawn `claude` via `pty.spawn` (the Claude CLI emits nothing under piped stdio), never `child_process.spawn`, never `shell: true`. Resolve-then-branch: `session/core/spawn-command.js` resolves `claude` once at module load; a real `.exe` is spawned directly, a `.cmd`/`.bat`/`.ps1` shim falls back to `cmd.exe /c claude`. Env is scrubbed by the pure `buildSpawnEnv` in `session/core/spawn-env.js` (unsets CLAUDECODE, CLAUDE_CODE_SSE_PORT, CLAUDE_CODE_ENTRYPOINT, GLISSA_PORT, GLISSA_CONFIG). All sessions share one Node event loop: no sync git or fs on recurring paths.
- **Session identity.** Sessions are keyed by a stable UUID `id`; `name` is display-only.

## Status detection, in brief

The original content-scraping stack (prompt regexes, line assembly, string blacklists) was deleted after the 2026-05-29 postmortem: screen content is for humans, and every Claude Code release broke the parser. Status now comes from structural signals only. Claude Code hooks are authoritative: the injected `--settings` file adds HTTP hooks (Stop, Notification, UserPromptSubmit, SessionStart/End, SubagentStart/Stop) that POST to `POST /hook/:glissaId/:event`, gated by a per-session bearer token. The OSC-0 title is the honest fallback: a spinner glyph means `working`, the idle glyph means `ready`, an unknown glyph is `unknown` (never a guess), and it never emits `awaiting-input`. `detection/status-source.js` merges the two with hook precedence, a conflict window that lets a racing `awaiting-input` beat a held `ready`, and dedup; the 7-state machine (INITIALIZING through DONE and FAILED) lives in `session/core/state-machine.js`.

The background-agent completion gate exists because a main-agent Stop can fire while background work (a sub-agent, a teammate, a background shell) is still running, which would falsely COMPLETE the card. `session/core/agent-tracker.js` counts live SubagentStart/SubagentStop ids and parses the authoritative `background_tasks` array from Stop payloads (the gate takes the max of counted and declared); `decideGateRelease` in `session/core/gate-release.js` is the ONE judge of whether a gate-held ready may complete the card (verdicts: cancel, gated, wait, release), with a quiet window (default 10s, `DEFAULT_GATE_RELEASE_SETTLE_MS`) and per-type TTLs (`agentTtlMs`, `shellTaskTtlMs`, `teammateTaskTtlMs`) so an idle teammate or an orphaned shell task cannot pin the card WORKING forever. Kill switch: `detectBackgroundAgents: false`.

## Opt-in lanes (all off by default)

- **PR auto-review** (`config.prReview.enabled` plus `config.telegram` credentials): `server/pr-poller.js` (IO-free, deps injected) polls the operator's own GitHub PRs, reviews each new head SHA in an ephemeral headless `claude -p` session (verdict via a result file, findings via `gh pr comment`), and merges only when reviewedHead still matches the current head, `gh pr checks` classifies green, and no `.github/workflows/` file is touched; no-checks and unknown both fail closed. Clean PRs are reviewed in place (diff-only); conflicting PRs get an isolated `git-workspace` worktree. Only the poller merges, never the agent. Telegram pings fire on actionable transitions only.
- **PostHog investigation lane**: a second ephemeral headless consumer registered through `server/ephemeral-session.js` (shared with the PR lane), seeded via `server/posthog-wiring.js` and consuming packs via `config.posthog.packs`.
- **Context packs**: a project record may carry `packs: ["name"]` (config.json only, deliberately not a control-WS settable key); spawn appends one `--add-dir <built dir>` per resolved pack plus `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` so the pack CLAUDE.md and rules actually load (live-verified on CC 2.1.235). Skills hot-reload into live sessions; CLAUDE.md and rules reach only the next spawn, so a rebuild broadcasts `pack-updated`, cards show a stale chip, and the next accepted UserPromptSubmit hook response injects a short Glissa-authored staleness notice (`session/core/pack-notice.js`, never pack content, so the live channel cannot become an injection relay). Pack sources are local files only; pack bytes land in `--dangerously-skip-permissions` sessions, so the trust boundary stays at files the operator already controls. The opt-in distiller (`config.packDistiller`, `server/pack-distiller.js`) regenerates derived source files with headless sessions; assembly itself stays deterministic and LLM-free.
