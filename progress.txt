## CONPTY FOCUS-STEAL FIX (ralph session, 2026-05-30)
Bug: pressing Enter in a glissa-managed Claude session raised/flashed the host VS Code
window on every send. Root cause: Claude Code fires UserPromptSubmit -> user's GLOBAL OMC
plugin command hooks (keyword-detector, skill-injector) spawn node.exe grandchildren ->
under node-pty's headless OS ConPTY those console spawns allocate a fresh console window
=> focus-steal raising the host terminal. Constraint (user): fix ENTIRELY in glissa's spawn
path; NEVER modify user settings or disable user plugins.

Fix (sessions.js only):
- buildPtyBackendOpts({platform, conptyMode}) pure helper. win32: 'dll'->{useConptyDll:true},
  'os-conpty'->{}, 'winpty'->{useConpty:false}, unknown->{}. non-win32-> {} always.
- conptyMode='dll' constructor option (this._conptyMode). Default 'dll' = node-pty's bundled,
  newer ConPTY (the same lever VS Code shipped for microsoft/vscode#136999), full fidelity.
- _spawnWithBackendFallback(): if the bundled dll fails to LOAD (node-pty throws), retry once
  with OS ConPTY (no flag). Guard keyed on backendOpts.useConptyDll so winpty/os-conpty real
  spawn errors are NOT masked -> still hit spawn_fail -> FAILED.
- Kill/restart unaffected: glissa tree-kills via `taskkill /PID <pid> /T /F` (kill(), start()
  pre-kill, _forceKillAfterTimeout, _handlePtyExit), independent of node-pty internal teardown,
  so the dll backend's different internal kill path cannot orphan the tree.
