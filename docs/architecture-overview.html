Glissa Architecture

Glissa is a lightweight Node.js background process that spawns and manages Claude Code sessions in real pseudo-terminals, streams their output to a browser dashboard over WebSockets, derives each session's status from structural signals (Claude Code hooks plus an OSC-0 title fallback, never screen scraping), and notifies the operator when a session needs attention. It binds to localhost only and runs as a single-user dev tool on the operator's machine.

The big picture

Three tiers: the browser dashboard, the Glissa server, and the Claude Code processes it manages. The server is a dumb pipe for terminal bytes and a smart broker for everything else.

How a session lives

Each dashboard card is one Session object owning one PTY. Sessions move through a seven-state machine with explicit, table-driven transitions; every transition comes from a structural signal, never from parsing rendered terminal output.

  • Spawn. pty.spawn launches claude (resolved once at module load; .exe direct, shim installs via cmd.exe /c), through a process-wide spawn gate that serializes ConPTY creation. A per-session managed --settings file injects HTTP hooks, an optional statusLine relay, optional rtk compression, and context packs via --add-dir. The env is scrubbed before spawn.
  • Crash safety. Every hook payload carries Claude's session id; Glissa persists it immediately, so after a crash or restart, boot auto-resume respawns previously active sessions with --resume. There is deliberately no shutdown flush.
  • Forensics. An always-on JSONL recorder writes every hook payload, transition, and gate decision to ~/.glissa/recordings; raw PTY bytes are opt-in.
  • Pure cores. Every decision that matters (state transitions, gate releases, merge demotions, notification categories) is a pure function in session/core/ with unit tests; sessions.js is the IO shell around them.

Status detection

The core design bet: status is derived from machine-emitted signals, never from what the terminal looks like.

  • Hooks POST to POST /hook/:glissaId/:event on the local server, authenticated by a per-session bearer token written into the managed settings file. The hook response is itself a channel: a UserPromptSubmit reply can inject a Glissa-authored pack-staleness notice into the turn.
  • /clear and /compact are quiet: the TUI redraw flashes a fake spinner, so title signals are latched off until the next real prompt.
  • The PTY data path parses nothing beyond scanning for OSC-0 title sequences.

The completion gate

The hardest detection problem: a main-agent Stop while background sub-agents, teammates, or shell tasks still run must not mark the card complete. One pure arbiter judges every held release.

Worktrees: isolation, auto-rebase, merge back

A session can run in its own git worktree so concurrent agents never collide in one checkout. server/git-workspace.js is the only module allowed to shell git worktree.

Notifications

A lifecycle state machine decides who gets told, when, and where. Terminal categories fire once per work cycle, and a work cycle starts only on a user-driven RUNNING entry, so a self-waking orchestrator cannot spam completions.

PR auto-review lane opt-in, tick every 15 min

Reviews the operator's own GitHub PRs with headless sessions and merges the clean ones unattended. The agent reviews; only the poller merges, behind a hard gate.

Radar: PostHog monitoring and auto-fix opt-in poll loop

Watches PostHog error tracking. A moved issue gets a diagnose-only investigation; with auto-fix on, a major issue (spiking, regressed, or new) gets a reproduce-then-fix agent.

Usage tracking on by default, 5 min scans

Reports language-model tokens and estimated list-price cost from local transcript files (Claude, plus Codex and Grok CLI trees). Never parses PTY bytes or rendered output.

Context packs: the context mill fs.watch + 15 min sweep

A pack gathers local docs, house rules, and curated skills into a versioned, token-budgeted directory a session is pointed at with --add-dir. Deterministic by contract: same spec plus same content yields byte-identical output, so the version is a hash.

Visions: live markdown co-editor opt-in, per keystroke

An editor relay speaks LSP over stdio and connects to a dedicated /visions WebSocket. Glissa mirrors the open documents and answers in tiers, from instant lint rules to a gated headless model dispatch.

Remote mode opt-in, config only

Remote access is a second listener, not a wider bind. A pairing cookie is treated as RCE-grade access: the control WS can spawn a permissionless session in any directory.

spawnSettings file written (hooks, statusLine, rtk hook), packs resolved to --add-dir, env scrubbed, PTY created, recorder armed.
per turnHook callbacks move the state machine; turn end triggers worktree diff recheck, post-turn hygiene checks, a debounced usage refresh, and possibly a notification.
continuousfs watchers on worktree gitdirs, integration-branch reflog, pack sources, and the pairings file; xterm renders whatever bytes arrive.
intervalsPR poller (15 min), pack sweep (15 min), usage scans (5 min, dashboard-gated), TTL prunes on agent tracking.
shutdownSignals route through one guarded handler that awaits PTY kill reaps (bounded 3 s) and exits. No config flush: persisted-at-hook-time state is the resume plan.
